# Fictional practice sources

Everything in this example is invented for practice. It does not describe a real organisation, project or person.

## Context

Prepare a concise weekly update for the procurement steering group. Use a neutral, professional tone. The update is accurate as at 14 September 2026. Use [S2] as the current task-status record, with [S3] supplying the later meeting decision record. Surface disagreements with the older email rather than treating an empty field as proof that an earlier assignment was cancelled.

## Sources

### [S1] Project lead email, 8 September 2026

The supplier comparison is complete. Morgan will own contract review. We expect final approval on 12 September and will start implementation on 16 September.

### [S2] Procurement task register, updated 13 September 2026

- Supplier comparison: complete, 10 September 2026.
- Contract review: in progress. Owner: not recorded.
- Security approval: pending. Decision required from the Security Review Panel.
- Implementation: target start 20 September 2026, conditional on security approval.
- Final commercial approval: status not recorded.

### [S3] Steering meeting note, 14 September 2026

The steering group asked for confirmation of the contract review owner. The Security Review Panel will consider the submission on 18 September. The note records no approval decision and no revised implementation commitment.

## What makes this useful

The older email [S1] conflicts with the later task register [S2]. The update must retain the verified completion of the comparison, but it must not repeat the old approval date, unconfirmed ownership or unconditional implementation date. The panel decision and missing owner need human attention.
